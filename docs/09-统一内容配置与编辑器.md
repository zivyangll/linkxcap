# 统一双语内容配置与编辑器

日期：2026-09-23。

## 1. 单一内容来源

除洞察文章外，可编辑的站点业务内容统一放在 `src/data/content.json`，包括品牌、SEO、导航、公共提示、页面文案、统计数据、团队、公司、联系方式、外部链接、洞察筛选项和 Fellow 媒体地址。

双语字段统一使用 `_cn`／`_en` 后缀。邮箱、日期、数字、结构标识和通用链接可共用。团队图片、公司 Logo、社交分享图和视频封面只在 JSON 中填写文件名，对应文件放在 `public/assets` 根目录；Figma 导出映射、字体子集和 Logo 几何仍是独立技术数据。说明性 Note 已移出业务 JSON，只在编辑器标题后显示为灰色括号说明，不需要填写或导出。

洞察文章不进入 JSON 编辑器。每个语言版本的标题、摘要、日期、分类、顺序、原文链接等元数据与正文统一保存在 `src/content/insights/*.md`。洞察列表、详情路由和 sitemap 都直接读取这些 Markdown 文件，不再维护 `list_rows` 或文章文件映射。Markdown 发布使用 HTML 清理插件，未允许的标签、属性和危险协议不会直接进入文章页面。

新增文章请复制 `src/content/insight-article-template.md`。文章的 `category` 必须与 `content.json` 中 `insights.filters[].id` 的具体筛选项一致；`all` 只表示“全部文章”，不能作为文章分类。完整字段说明和操作步骤见 [洞察文章 Markdown 模板与筛选关联](10-洞察文章Markdown模板与筛选关联.md)。


部署到当前 GitHub Pages 后，对应地址将是：

```text
https://zivyangll.github.io/linkxcap/a4f9c2e71b6d4830c5a8e2f94d7b136c.html?debug=true
```

本轮没有推送或部署，因此线上地址只有在后续发布本次代码后才会生效。

只有查询参数恰好包含一次 `debug=true` 时，页面才动态加载编辑器模块和配置 JSON。缺失、值错误或重复的 `debug` 参数都只显示不可访问状态。入口不在导航和 sitemap 中，页面设置 `noindex,nofollow`。

固定哈希地址和查询参数只是隐藏入口，**不构成身份认证或权限保护**。生成的静态资源仍可能被知道地址的人访问，不得在配置中保存密码、令牌、私钥或其他敏感信息。

## 3. 自动保存和草稿恢复

- 修改任意输入项时，同步把完整表单保存到 `localStorage`，不需要点击保存。
- storage key 同时包含当前域名与 `schemaVersion`：`linkx-content-editor:<hostname>:schema-13`。
- 再次进入页面时优先恢复本地域名下的兼容草稿；没有草稿时使用项目内默认配置。
- JSON 损坏、结构不完整或版本不兼容时不会静默覆盖原草稿，页面会显示原因并暂用默认配置。
- localStorage 被禁用或容量不足时会显示“保存失败”，当前内存内容仍可导出。
- 本地草稿不会改变公开网站。发布必须执行“导出 JSON → 替换 `src/data/content.json` → 构建 → 部署”。

## 4. 导入 JSON

1. 点击“导入 JSON”并选择 UTF-8 JSON 文件，最大 2 MB。
2. 编辑器先解析并校验 `schemaVersion`、完整结构、字段类型、必填字段、唯一 ID、公司与投资领域关联以及链接协议。
3. 校验通过后显示“将覆盖当前全部表单和本地草稿”的确认提示。
4. 确认后使用文件内容完整替换当前配置和 localStorage，不与旧配置合并。
5. 取消、非法 JSON、危险对象字段、错误类型、危险链接或存储失败时，当前表单和草稿保持不变。
6. 文件选择器每次清空，可连续导入或重复选择同一个文件；最后一次成功导入的数据为准。

编辑器使用 DOM `textContent` 和表单 `value` 展示导入内容，不使用 `innerHTML`，也不会执行 JSON 中的脚本字符串。

## 5. 导出 JSON

1. 点击“导出 JSON”。
2. 编辑器校验当前内存中的最新完整配置；存在问题时列出具体路径并停止导出。
3. 通过后下载 UTF-8、两空格缩进的 `content-YYYY-MM-DD-HHMMSS.json`。
4. 导出的文件保留 `schemaVersion` 和全部 JSON 业务配置，可再次完整导入；洞察文章仍由 Markdown 独立管理。
5. 即使 localStorage 写入失败，只要当前内存配置有效，仍允许导出以避免内容丢失。

## 6. 表单结构和只读字段

编辑器按全站设置、导航与公共文案、首页、投资组合、团队、洞察公共设置、联系方式和媒体、法律声明分组，并使用顶层 Tab 每次只展示一个分组。中英文对应字段并排显示，长文本使用多行输入，数字、布尔值和数组按原始类型编辑。

公司和团队成员各自使用记录 Tab：点击 Tab 编辑该条记录，修改中英文名称时 Tab 名称同步变化；支持新增、删除、鼠标拖动排序以及触摸设备的上下移动按钮。新增按钮使用圆角光感样式，删除操作使用可取消的自定义确认弹窗。公司数组本身的顺序就是前台展示和详情导航顺序，不再维护单独的 `company_order`。

页面中的 `Eyebrow` 指主标题上方的短标签，例如 “ABOUT US” 和 “OUR TEAM”。编辑器统一显示为“标题上方辅助小字”，并对首页轨道、加入我们和联系模块提供更具体的中文字段名。Fellow 媒体只配置视频地址和封面地址，不配置字幕或视频状态。

公司 `slug` 可以编辑，格式仅允许小写字母、数字和连字符。它直接决定双语详情页地址；导出 JSON、替换 `content.json` 并重新构建后，投资组合列表、详情导航、首页拓扑链接和 sitemap 会一起使用新地址。旧 slug 对应的页面不会继续生成，如需保留旧链接，应在静态服务器配置重定向。

公司和团队成员的内部 `id` 不再显示在编辑器中，由系统在新增记录时自动生成并继续保存在 JSON 中。公司 `id` 用于绑定已有 Logo 几何、首页拓扑位置和交互；团队 `id` 用于页面内头像与简介联动。两者都不参与公开详情页地址。

公司和团队成员都提供可编辑的 `slug`。公司地址为 `/portfolio/<slug>.html`，团队成员地址为 `/team-<slug>.html`；中英文使用相同 slug。修改后重新构建时，列表链接、语言切换、详情页和 sitemap 会同步更新，旧 slug 页面不再生成。文章 `route` 和导航 `page` 仍为只读结构字段。
