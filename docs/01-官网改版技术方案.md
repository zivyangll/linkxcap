# 星连资本 Link-X Capital 官网改版技术方案

版本：2026-09-18 · 范围：分析与方案，不含网站实现或部署。

**建议采用 Astro 静态生成，将品牌叙事的动效集中在首页，并以 SVG 曲线和少量 Canvas 粒子构成科技感。** 投资组合、团队和洞察以阅读、检索、访问详情为主。这样更符合稿件中米白、衬线字体、细线轨迹和克制紫色的品牌气质，也便于满足双语、移动端和静态部署要求。

已确认：首次 GitHub Pages；Fellow 合并到首页及联系页；Insight 提供站内中英文详情及原文链接。其余未确认内容在文中明确标注。

## 1. 设计稿与现有官网分析

### 1.1 本轮实际访问与读取范围

| 对象 | 实际结果 | 结论边界 |
| --- | --- | --- |
| [现有中文首页](https://www.linkxcap.com/zh/index.html) | 浏览器可访问；读取导航、品牌介绍、业务方向、数字和页脚，并访问 Portfolio、Team、Insight、Contact、Legal 及部分详情 | 列表的内容需要浏览器执行脚本才能完整看到；未对所有外链做可用性检查，未完整校对每篇英文文章 |
| [Figma final](https://www.figma.com/design/CTEAWCezlfopOXN5WcsqMa/Link-X--Copy-?node-id=2002-2) | 有读取权限；读取 final 下 2,107 个节点、5 组、28 个直接子级桌面画板，并检查文字、图片占位及交互属性 | 未发现可执行的 reactions、动画时间线或视频填充；未发现独立移动端画板；不把静态分镜当成已定义动效 |
| [Apple iPhone 18 Pro](https://www.apple.com/iphone-18-pro/) | 本轮链接可访问，已观察首屏、局部导航、亮点画廊及不同章节的视觉层次 | 无须替换链接；未测量其性能，也未确认其底层实现库 |

Figma 明确可见的交互说明只有 Portfolio 的“右侧可滚动”和 Team 的“Hover 展示信息”等文字标注。首屏进入时长、滚动固定距离、曲线绘制方向、粒子数量以及页面转场，均需由本方案提出并通过原型确认。[画板和差异证据](03-调研记录与设计差异.md)

### 1.2 页面与导航范围

采用多页面静态网站。Philosophy 对应首页及其 About/Focus 章节；暂不再增加内容重复的独立 Philosophy 页面。

| 页面／模板 | 模块与依据 | 导航及上线范围 |
| --- | --- | --- |
| 首页 / Philosophy | Open Signal → 品牌主张 → About → 经批准的数据 → 深色 Focus 五领域；合并 Fellow 的 The Next Signal 摘要和 Join Us 入口 | Logo 返回首页；导航 Philosophy 指向首页的品牌介绍锚点；章节顺序为本方案建议，需用滚动分镜确认 |
| Portfolio 列表 | Figma 19 个 Logo 卡位、灰阶／高亮、公司名及分类、进入详情箭头 | 19 家是现官网公开样本，不代表全部投资数量；展示名单和顺序待确认 |
| Portfolio 详情模板 | Figma Z.AI 与 MOSI 两个示例；公司说明、官网按钮、右侧弧形导航 | 为获批公司生成独立可访问 HTML；右侧导航渐进增强，不能成为访问其他公司的唯一方式 |
| Team 列表 | 线描人像、姓名、职务；hover 展示简介和投资项目 | Figma 6 个位置只有 4 位不同成员；按现官网 4 位作为内容盘点基线，最终人数待确认 |
| Team 详情模板 | 原网站已有 4 个成员详情 URL；Figma 无独立详情稿 | 保留现有详情，沿用新版字体、版心和卡片语言补充设计；列表摘要不替代完整简介 |
| Insight 列表 | 文字新闻行、日期、分类、筛选、阅读全文；Figma 长列表无封面图 | 当前网站有 6 篇不同文章；Figma 7 行仅 4 个不同标题，重复行不转为新文章 |
| Insight 详情模板 | 用户确认新增要求；现有文章已含目录、正文、分享和返回列表 | 生成独立中英文详情；保留原文链接，原文 URL 未提供时不造链接 |
| Contact | 原网站联系信息＋Fellow Join Us／Build with us | 无独立完整联系页设计稿，需补齐；默认邮件、二维码及社交账号，无提交表单 |
| Legal | 保留现站免责声明、知识产权、隐私等内容结构 | 中英文正文由公司复核；增加真实存在的页脚入口 |
| 404／语言入口 | 开发补充 | 真实静态 404；站点根入口提供中英文选择 |

预估内容上限基线为每语言 6 个基础页面（首页、Portfolio、Team、Insight、Contact、Legal）＋19 个公司详情＋4 个成员详情＋6 篇文章，即 **35 页／语言，约 70 个内容 HTML**，另有入口和 404。实际页面数量以批准的公司、团队和文章清单为准；只有约 10 类页面模板，不是 70 套独立视觉设计。

### 1.3 设计特点、继承内容与冲突

- **已有视觉**：米白背景（不同画板出现 `#FDFBF5`、`#F8F6F2`）、近黑文字 `#1D1D1D`、紫色 `#573C79` 与浅紫节点、衬线标题、极细点线和菱形标记。需要先统一色彩 token，避免无意保留多个近似底色。
- **已有字体**：Source Han Serif SC 多字重、Source Serif 4 Italic、LXGW Neo XiHei。字体文件、版本和 Web 使用授权需交付；不一次加载所有中文全量字重。
- **继承内容**：品牌背景、投资方向、公司名单、团队资料、文章、邮箱、二维码、社交链接和法律／备案信息。现站 URL 尽量原样保留。
- **关键冲突**：首页现站 `70+ / 2000+`，稿件 `160+ / 68+ / 25+ / $100B+` 且多个指标标签重复；王璞现站为 Elliot Wang / Partner，稿件为 Pu Wang / Managing Partner，经历和投资项目也不同；MOSI 详情复制 Z.AI 介绍；领域卡片有重复文案；“生树／生数”“原木／圆木”“RELAI／REALAI”不一致。全部待公司定稿，不能凭设计稿替换事实。
- **缺稿**：360px 手机及平板、文章详情、成员详情、完整 Contact、Legal、404、菜单键盘状态、筛选空状态、视频错误状态等。以现有视觉语言补齐，并纳入移动端验收。
- **原站问题**：首页 EN 链接实际指向 `/zh/en/`，中文链接指向 `/zh/zh/`；部分列表在文本抓取时没有公司数据，浏览器执行后才展示。新版应在构建时生成正文和链接。

### 1.4 苹果参考如何转化

借鉴已观察到的章节分组、巨幅标题与留白、媒体与文字的分层、清晰局部导航、可操作的画廊和浅深场景对比。星连的首页采用“看到信号 → 理解机构 → 理解领域 → 发起联系”的节奏，不引入与信息无关的长距离滚动。具体参数以星连内容密度和移动端实测决定；不推断苹果使用何种动画框架。[参考页面](https://www.apple.com/iphone-18-pro/)

## 2. 技术选型结论

### 2.1 三种组合对比

| 组合 | 设计与动效 | 首屏与运行 | 中英文／SEO | 维护、静态交付与风险 |
| --- | --- | --- | --- | --- |
| **Astro 静态生成＋TypeScript＋GSAP/SVG/Canvas（推荐）** | 组件组织各模板；动效脚本只在需要的页面挂载，适合本稿 | HTML 默认可直接阅读；页面间不必加载框架运行时；Canvas 只负责装饰 | 每语言独立 HTML；结构化内容统一生成列表、详情、SEO | Markdown/JSON 更新后重建；输出 dist；主要风险是长篇双语排版、动画清理和素材交付，不是服务器 |
| Vite＋TypeScript 原生多页面＋同一动效层 | 自由度高，适合页面较少且维护者熟悉原生前端 | 可非常轻；但性能仍由媒体和动画控制 | 需要自行实现内容模板、动态生成页面、翻译映射和 sitemap 流程 | 静态部署简单；本项目几十个详情页面会增加自研构建与校验工作，不作为首选 |
| Next.js 静态导出＋React＋按需动效 | 交互能力强；若后续升级业务应用可复用 | 需谨慎控制客户端组件和 hydration 成本，避免纯内容页面承担额外 JS | 可生成双语静态页面；所有动态路径在构建时确定 | 可导出静态文件；服务端功能不可用于纯静态发布，本轮不需要其主要优势；若已有成熟 React 团队才考虑 |

以上为工程判断，不是框架跑分。静态输出与构建能力参考：[Astro 配置](https://docs.astro.build/en/reference/configuration-reference/)、[Vite 构建](https://vite.dev/guide/build.html)、[Next.js 静态导出](https://nextjs.org/docs/app/guides/static-exports)。实施时选择当时的稳定版本并固定 lockfile。

### 2.2 主推荐的组成

| 层 | 选择 | 本项目中的职责 |
| --- | --- | --- |
| 页面 | Astro 静态输出＋TypeScript | 共用 Header/Footer、页面模板；生成所有可直达 HTML，不依赖运行时数据库 |
| 内容 | 构建期 JSON＋Markdown 内容集合与 schema 校验 | JSON 保存公司、成员、导航、文案、分类、路径；Markdown 保存双语文章；引用稳定 ID，不按名字连接数据 |
| 样式 | CSS 自定义属性＋组件局部样式＋少量公共排版规则 | 色彩、间距、字号、层级、动效时长统一；无需为本项目引入大型 UI 组件库 |
| 轻交互 | CSS transitions、少量原生 TypeScript | 菜单、焦点、按钮、筛选、触摸展开；真实链接始终存在 |
| 滚动叙事 | 按需导入 GSAP＋ScrollTrigger | 首页时序、曲线显现、局部固定；用 matchMedia 为宽屏、手机和 reduced-motion 建立不同配置并清理 |
| 几何视觉 | SVG | 点线路径、菱形、轨道、Focus 连线；画质稳定且可提供静态图形 |
| 粒子 | Canvas 2D，单个可见装饰场景 | 稀疏星点、轻漂移、亮度变化；不把标题和点击目标绘入 Canvas |
| 可选真实 3D | 经原型验证后独立引入 Three.js/WebGL | 仅针对确需三维转动／空间遮挡的新增场景；默认不安装、不计入基础交付 |
| 发布 | GitHub Actions 构建→Pages artifact→Pages | Node.js 只用于构建；产物可整体迁移到任何静态服务器 |

内容集合可在构建时读取 Markdown/JSON 并做结构校验；GSAP 的媒体条件配置用于不同视口和减弱动效模式的创建与回收。[Astro 内容集合](https://docs.astro.build/en/guides/content-collections/)、[GSAP matchMedia](https://gsap.com/docs/v3/GSAP/gsap.matchMedia()/)

### 2.3 可维护性约束

- 暂按开发人员通过 Git 更新内容；公司对接人填写素材表，开发校验并合入。若运营必须直接编辑网页内容，再单独评估构建触发式 CMS，不将其作为一期隐含依赖。
- 每条实体采用稳定 `id`、`slug`、`zh/en` 文案、来源 URL、发布日期或审核日期、发布状态；未批准的统计数字和测试内容不得进入正式构建。
- 每篇中英文文章建立同一 translation key；缺失翻译使发布校验失败或明确排除该篇的两种语言，不能用中文正文冒充英文版。
- 内容和动效解耦：关掉所有动画模块后，导航、所有正文、公司官网与联系入口仍可正常使用。

## 3. 逐模块动效与响应式方案

标记：**D＝稿件已有静态设计或文字标注；I＝从画板关系推断的交互；R＝建议新增。** 本节所有具体时长、缓动、粒子数和触发阈值均为 R，待原型测试后冻结。

### 3.1 动效实施表

| 页面／模块、依据 | 视觉目的 | 触发方式 | 实现技术 | 桌面端表现 | 移动端表现 | 成本与降级 |

断点按内容溢出调整，768／1024／1280 为初始值。标题采用流式字号和人工校对的语义换行，不逐字绝对定位；中英文独立行高和最大宽度，英文可多行而不缩成难读小字。SVG 为手机另设 viewBox/轨迹，避免简单裁切导致节点消失。关键正文对比度按 WCAG AA 目标检查（普通文本 4.5:1）；浅紫小字、浅灰日期需要实测调整。[WCAG 最小对比度](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)

## 4. 性能预算与验收方法

### 4.1 传输预算（立项约束，尚未实测）

以下“KB”按约 1,000 字节理解；HTML/CSS/JS 指服务器实际压缩后的网络传输体积，图片／字体指文件传输大小。若 Pages 某资源未压缩，也按实际传输计，不拿本地 Brotli 理论值代替。

| 项目 | 手机首页目标 | 桌面首页目标 | 执行方法 |
| --- | --- | --- | --- |
| 首屏关键资源总量 | ≤500KB | ≤750KB | 包含 HTML、首屏 CSS/JS、Logo、首屏字体与海报；不含用户点击才下载的视频 |
| LCP关键路径资源 | ≤300KB | ≤450KB | 上一行的子集：只让实际影响首个主要内容显示的HTML、CSS、必要字体／图片进入关键路径；粒子与非关键媒体延后 |
| HTML | ≤50KB | ≤60KB | 全部语义正文静态生成；避免内联大数据和重复中英全文 |
| CSS 总计 | ≤35KB | ≤40KB | CSS变量和组件局部样式；不用巨型通用组件样式包 |
| LCP 前必需 JS | ≤30KB | ≤40KB | 正文无需 JS；菜单与基础交互轻量；GSAP/Canvas 排在可读内容之后 |
| 首页完整交互 JS（延迟模块也计入） | ≤120KB | ≤150KB | 包含 GSAP、ScrollTrigger、Canvas 自身代码；实测超限先删不必要效果 |
| 普通列表／文章页 JS | ≤45KB | ≤45KB | 不加载首页动画包或粒子库 |
| 首屏字体 | ≤160KB | ≤200KB | 只预载需要的字体子集；非关键字体不阻塞可读内容 |
| 首屏图片／静态背景 | ≤180KB | ≤300KB | 设计以矢量和留白为主；若使用海报须纳入总量预算 |
| 首页首次完整阅读、未播放视频 | ≤1.2MB | ≤1.8MB | 包含滚动后懒加载的必要素材；单项上限不可全部同时用满 |
| 人像单张、Logo 单个 | 人像≤90KB；Logo尽量≤20KB | 人像≤160KB；Logo尽量≤20KB | SVG优先，复杂Logo用透明WebP；保留高清源文件但不直接发布 |
| 可选循环视频 | 手机默认不下载；点播720p≤2MB | 8–12秒1080p短片初始预算≤4MB | 时长是建议规格；复杂镜头压缩后仍超限则静态替代；长访谈另按内容核定 |

图片用 AVIF/WebP＋兼容回退、`srcset/sizes`、固定宽高或 `aspect-ratio`；LCP 图不 lazy-load 且不等 JS 注入。只对确实是 LCP 的候选使用高优先级，其他图分阶段懒加载。

### 4.2 字体、渲染和生命周期

- 中文正文优先系统宋体／经过验证的 serif fallback；品牌标题使用授权 WOFF2 子集。仅按公开内容子集化，构建时检测新增汉字覆盖；文章量增长后按合理 Unicode 分段，避免每篇重复携带同一大字体。
- 英文按稿件使用一个正文／标题家族和必要 Italic；初期尽量控制在 2–3 个实际字体文件。`font-display: swap`，通过 fallback 字体度量、固定媒体比例和预留标题空间减少 CLS。
- Canvas 初始 DPR 上限：手机 1.5，桌面 1.75；活动像素上限约 2MP／4MP，超宽屏降低 DPR。每次仅一个可见 Canvas；Canvas 本体全透明区域也会消耗像素预算。
- 动画预算：交互／滚动以 60fps 为目标（约16.7ms／帧），装饰粒子可30fps；中端手机持续动画主线程脚本 p95 尽量≤6ms／帧。持续滚动录制中不应反复出现由动画引起的 >50ms 长任务。该预算须在实机验证，不按粒子数量推定合格。
- 以 `IntersectionObserver`＋`visibilitychange` 管理可见性；离开场景、标签页后台立即取消 rAF/暂停视频，而非只把 opacity 设为 0。释放监听器、GSAP timeline、Canvas backing store；如启用 WebGL，处理失去上下文并 dispose 纹理／几何体。
- 根据实测帧耗时连续超预算降低点数／DPR，再降静态；避免频繁来回切档。`deviceMemory`、`hardwareConcurrency`、`saveData` 仅作有则使用的提示，Safari 缺失时仍能运行和降级。
- 不以滚动事件同步计算所有粒子、不全点两两连线、不为几十张卡片永久设置 `will-change`。避免全屏高半径 blur、巨大离屏层、同时播放多个视频。

### 5.2 静态 SEO

- 每页在 HTML 中生成唯一 title、description、`html lang`（zh-CN/en）、绝对 canonical、双方互链 `hreflang`；可用语言选择入口作为 `x-default`。文章和公司页面 canonical 指向其具体详情，不指向首页。
- 输出 sitemap.xml，包括获批的公开详情与双语关联；生成 robots.txt、Open Graph／社交卡片。结构化数据只使用已确认的 Organization、Article、Breadcrumb 字段；作者／日期未知时不编造。
- 暂存预览在真实品牌官网仍运行时设置 noindex，避免两套域名同时索引相同内容；正式发布再切生产配置。不要同时 Disallow 全站又期待爬虫读取 noindex。
- 正文、导航与详情链接须出现在初始 HTML。筛选结果不制造大量可索引重复页；必要时设独立分类页才进入 sitemap。
- 正式 canonical 域名由最终发布地址决定；GitHub Pages 预览不提前冒充已经上线的 linkxcap.com 新站。[Astro 国际化](https://docs.astro.build/en/guides/internationalization/)

### 5.3 GitHub Pages 首次部署

仓库 remote 已读取为 `zivyangll/linkxcap`。如采用默认项目站点，**预计**地址为 `https://zivyangll.github.io/linkxcap/`；这不是已经部署成功的地址。

1. 配置 `site` 为实际域名，`base` 为 `/linkxcap/`；生产自定义域名根部署改为 `/`。所有内部链接、资源、分享链接与 sitemap 都经过同一个 URL 辅助函数，不手写根路径。
2. 使用 Astro 静态输出及能保留 `index.html` 的路径生成策略。建议 `build.format: 'preserve'` 配合明确的页面文件；在构建测试中验证 `/zh/index.html`、嵌套详情和根入口都真实存在。不要假定任意构建格式都会产生同样路径。
3. GitHub Actions 安装锁定依赖、内容校验、构建、链接/路径/体积检查，再上传 dist 并发布 Pages。部署阶段使用最小必要权限；不把令牌写入前端或构建产物。
4. dist 含 `index.html`、`zh/`、`en/`、哈希资源目录、`404.html`、robots、sitemap，以及按发布方式需要的 `.nojekyll`；绑定自定义域名时增加 CNAME 并配置 DNS/HTTPS。
5. 每个详情直接访问及刷新都由真实文件响应。不存在的地址返回真正的404页面；不使用把所有错误改成 index.html 的 SPA fallback。

GitHub Pages 支持静态文件与 Actions 发布，但不提供应用服务端；Astro 官方给出了项目路径下 site/base 的配置要求。[GitHub Pages 说明](https://docs.github.com/en/pages/getting-started-with-github-pages/what-is-github-pages)、[Astro GitHub 部署](https://docs.astro.build/en/guides/deploy/github/)

### 5.4 URL 迁移与服务器配置边界

| 项目 | GitHub Pages 一期做法 | 迁移到可配置静态服务器／CDN后 |
| --- | --- | --- |
| 旧URL | 尽量保留文件名；页面内容由新模板输出。不可避免改名时保留静态说明／跳转文件及 canonical，注明它不是HTTP301 | 建立经过核对的301映射，保留查询参数和锚点意图；更新站内链接及sitemap |
| 缓存 | 平台控制响应头，不能靠仓库里的Nginx配置生效；哈希文件名防旧资源错配，按实测记录缓存 | HTML短缓存／需验证；哈希资源 `max-age=31536000, immutable`；传输压缩和字体MIME配置 |
| 404 | 根404.html；包含中英返回入口且资源带base；默认返回404状态 | 配置自定义error_page并保留404状态，不改200 |
| 压缩和头部 | 验证平台实际 gzip/Brotli 行为；`.htaccess`及自定义Nginx头无效 | 启用gzip/Brotli、正确MIME、HTTPS，配置需要的安全响应头 |
| 大陆与海外 | 所有关键资源同站托管，不依赖Google Fonts或公共CDN脚本；实测Pages线路 | 根据访客地区选择可达的CDN／对象存储，静态产物无需改应用架构 |

原站首页已有异常语言链接，可在新站增加 `/zh/en/index.html`、`/zh/zh/index.html` 等有限兼容入口，但先以爬取清单／流量记录确认需要，不生成无限别名。跨域迁移若没有旧域名控制权，新仓库无法替旧服务器返回301。

Pages 对站点和流量有公开限制（如发布站点1GB、每月100GB软流量限制），最终应在发布前复核；高码率视频源文件不放进发布目录。自定义404按官方方式输出。[Pages 限制](https://docs.github.com/en/pages/getting-started-with-github-pages/github-pages-limits)、[自定义404](https://docs.github.com/en/pages/getting-started-with-github-pages/creating-a-custom-404-page-for-your-github-pages-site)

- 若必须在线提交 BP／简历：需要外部表单／存储／反垃圾服务，并重新确认隐私告知、附件限制、收件人与错误提示；纯静态目录本身不能收件或安全保存秘密密钥。该服务不属于已确认一期。
- 新闻与团队更新通过改内容文件后重建发布。直播数据、实时招聘或第三方后台接口目前均不在已确认范围。

### 7.2 最终开发交付应包含

1. 完整源码、锁定依赖、构建脚本、示例环境配置；无需运行期秘密信息。
2. 可直接上传的 `dist/`：双语HTML、CSS/JS、优化资源、404、sitemap、robots、favicon/OG；Pages与品牌域名两种构建说明。
3. 原始素材清单及授权记录、Web优化版本、Logo和公司/成员/文章映射；源视频不混入发布包。
4. 动效规格表：时长、缓动、触发范围、桌面/手机/reduced-motion差异、资源预算及销毁方式。
5. 内容维护文档：加文章、改团队、加公司、双语校验、换图、预览、发布、回退。
6. 验收证据：设备和网络条件、资源体积、实测性能报告、关键视口截图、无JS/降级检查、内外链结果；注明未覆盖场景。
7. 旧新URL映射和域名切换说明；一份可重放的构建与部署记录。

本轮只交付本方案、素材表与调研证据，不提前创建应用代码、部署工作流或发布站点。
